================================================================================
KEYSPRINT — COMPLETE SITE DOCUMENTATION
================================================================================
A free online typing test, typing speed measurement and touch-typing lesson
platform. Built with Astro + Tailwind, fully statically generated, no accounts,
no backend, no database, no analytics.

Project location : C:\Users\pinky\Videos\typing
Package name     : keysprint (v1.0.0, private)
Node requirement : >= 22.23.4
Default domain   : https://keysprint.onrender.com (override with env SITE_URL)

================================================================================
1. WHAT THE SITE IS
================================================================================

Three things in one place:

  1. A TYPING TEST — timed runs of 15, 30, 60, 180, 300 or 600 seconds that
     report words per minute and accuracy, with a per-key breakdown afterwards.

  2. A TEN-LESSON TOUCH-TYPING CURRICULUM — from the home row through to a
     60-second mixed paragraph, each lesson with its own passage, its own
     accuracy target and its own progress record.

  3. PRACTICE MATERIAL — words, sentences, paragraphs, numbers and punctuation
     drills drawn from an original text corpus.

Everything runs in the browser. There is no sign-up, no server-side storage and
no third-party tracking. The only things saved are the visitor's best scores,
their recent test history, their theme choice and their lesson progress — all in
their own localStorage.

4. THE TEN-LESSON CURRICULUM
================================================================================

Defined once in src/lib/lessons.ts. Both the lesson player and the lesson index
read that file, so there is a single source of truth.

Lessons 1–9 are UNTIMED SEQUENCE DRILLS: complete the passage at or above the
accuracy target. Lesson 10 is a TIMED 60-SECOND test with live WPM.

 #  ID                     TITLE                    FOCUS                   PASS TARGET
 1  home-row               The home row             a s d f · j k l ;       96% accuracy
 2  index-fingers          Index fingers            f g r t v b · j h u y n m  95%
 3  middle-fingers         Middle fingers           d e c · k i ,           95%
 4  ring-fingers           Ring fingers             s w x · l o .           94%
 5  little-fingers         Little fingers           a q z · ; p /           94%
 6  upper-row              Upper row                q w e r t y u i o p     93%
 7  lower-row              Lower row                z x c v b n m · , . /   93%
 8  capitals-shift         Capitals and Shift       Shift + letters         92%
 9  numbers-punctuation    Numbers and punctuation  1–0 · ! @ # $ % & * ( ) ?  90%
10  mixed-practice         Mixed practice           all keys · 60 seconds    90% AND >= 120 characters

Each lesson carries:
  id, order, title, metaTitle, metaDescription, lead, instructions, focus,
  text (the passage typed), minAccuracy, timedSeconds (null = untimed),
  minCharacters, two paragraphs of notes, three practice tips.

Completion rules (src/lib/lesson-rules.ts, imported by the player so the lesson
text is NOT bundled into the player's JavaScript):

  Sequence drill (timedSeconds === null):
    - whole passage must be typed
    - accuracy must be >= minAccuracy
    - otherwise: 'unfinished' or 'accuracy'

  Timed drill:
    - clock must have run out OR the passage must be finished
    - at least minCharacters typed (else 'too-short')
    - accuracy >= minAccuracy (else 'accuracy')
    - passing => 'passed'

  Possible outcomes: 'passed' | 'accuracy' | 'unfinished' | 'too-short'

Lesson 10 deliberate design choice: WPM is shown, because a 60-second paragraph
run genuinely measures speed. Lessons 1–9 deliberately show elapsed time and
progress but NO WPM, because a short teaching sequence is not a speed
measurement — showing a speed number there would be misleading.

5. LESSON PROGRESS (localStorage)
================================================================================

Module: src/lib/lesson-progress.ts

Storage keys:
  keysprint.lessons.v1        one record per lesson (status, bests, timestamps)
  keysprint.lesson-draft.v1   the single attempt currently in progress

Lesson record shape:
  { status: 'started' | 'completed' | 'skipped',
    bestAccuracy: number,     // 0–100
    bestWpm: number,
    lastAttemptAt: ISO string,
    completedAt?: ISO string  // only when completed }

Draft shape:
  { lessonId, typed, elapsedMs, keystrokes, correctKeystrokes, savedAt }

Behaviour that matters:
  - A draft expires after 7 days (LESSON_DRAFT_TTL_MS). An attempt from a month
    ago is not the same sitting.
  - RELOAD RECOVERY: reloading mid-lesson restores the buffer, the elapsed time
    and the raw keystroke counters. The restored attempt reopens PAUSED, with a
    "Picked up where you left off" note and a Resume button, so the time spent
    re-reading is not counted against the visitor.
  - RESTART SCOPE: restarting clears only that lesson's draft and attempt. It
    never touches the other nine lessons, best scores or the theme.
  - Best accuracy and best WPM only ever improve. A completed lesson can never
    be downgraded by a later weaker attempt.
  - Skipping a lesson unlocks the next one but is recorded as 'skipped', not
    'completed', so the curriculum stays honest about what was actually learned.
  - Everything is defensive: private/blocked storage throws on access, damaged
    JSON is dropped rather than repaired, and non-finite numbers fall back to 0.

6. THE TYPING ENGINE
================================================================================

Module: src/lib/typing/engine.ts  (class TypingEngine)

Deliberately DOM-FREE. It takes a timestamp argument on every call, so the caller
decides how time advances (the widget uses requestAnimationFrame; the tests use a
fake clock). This is what makes the scoring deterministic and unit testable.

State machine:
  idle      nothing typed yet, clock not started
  running   clock running, characters accepted
  paused    clock stopped, input rejected, buffer and time-so-far KEPT
  finished  clock expired or caller ended the run; all further input ignored

Key methods:
  start(now)                           start the clock
  pause(now)                           stop the clock, keep the buffer
  resume(now)                          restart, excluding the paused gap
  restore(typed, elapsed, ks, cks, now) rebuild from a persisted draft
  reset()                              clear buffer, keep passage
  setText(text, durationMs)            swap passage and reset
  type(char, now)                      record a character; returns its index
  backspace()                          delete the last character
  tick(now)                            advance time; returns true once, on finish
  finish(now)                          end the run
  getStats()                           full statistics object
  getCharacterStates()                 per-character 'pending'/'correct'/'incorrect'
  getKeyTallies()                      per-key tallies for the heat map

Correctness guarantees built in:
  - Monotonic timing: elapsedMs never goes backwards and is never negative.
  - Paused time is subtracted from elapsedMs AND added to the deadline, so a
    pause neither lowers a WPM score nor shortens the clock.
  - A run that finishes while paused freezes the clock at the moment of the
    pause, so the paused gap is not counted as typing time.
  - tick() finishes on the DEADLINE, not on the current timestamp. A
    backgrounded browser tab can deliver a late frame; counting that gap as
    typing time would understate the score.
  - Completion fires exactly once. Calling tick() or finish() again is a no-op,
    so no score can change after the run has finished (no duplicate events, no
    score inflation).
  - Backspace intentionally does NOT reduce the raw keystroke counters. Those
    describe what your fingers did, not what ended up on screen.
  - restore() treats stored values as untrusted: the buffer is clipped to the
    target length, counters are clamped, and non-finite values fall back to
    sensible defaults.
  - An empty restore() returns the engine to idle with zeroed counters, so a
    stale draft can never leak into the next attempt's keystroke accuracy.
  - Every statistic is guarded against division by zero: a zero-length buffer or
    zero elapsed time returns 0, never NaN or Infinity.

Supported typing states: 'idle' | 'running' | 'paused' | 'finished'
Character states:          'pending' | 'correct' | 'incorrect'

7. SCORING FORMULAS
================================================================================

Defined once in src/lib/typing/scoring.ts and verified by unit tests. One "word"
is five characters (the standard conversion).

  gross WPM        = (characters / 5) / minutes
  net WPM          = ((characters - errors) / 5) / minutes
  character acc.   = (characters - errors) / characters * 100
  word accuracy    = correctWords / words * 100
  keystroke acc.   = correctKeystrokes / keystrokes * 100
  error count      = characters in the buffer that differ from the target

Where:
  characters         characters currently in the buffer
  errors             buffered characters that differ from the target
  keystrokes         total character input events, INCLUDING later-deleted ones
  correctKeystrokes  input events where the character matched
  words              whitespace-separated words currently in the buffer
  correctWords       words matching the target word at the same position
  minutes            elapsed ms / 60000, excluding paused time

The important distinction:
  - Character accuracy looks at the buffer AS IT STANDS, so fixing a mistake
    with backspace restores the score.
  - Keystroke accuracy does NOT. It keeps counting a mistake even after you
    delete and fix it, which is the honest measure of raw keyboard accuracy.
  - Net WPM is the number to trust, because it rewards accuracy over speed.

Every formula returns 0 for degenerate input (empty buffer, zero or negative
elapsed time), so the UI can never display NaN or Infinity.

9. KEY SOUNDS
================================================================================

Module: src/scripts/key-sound.ts

Three short recorded samples, each encoded into three formats so every browser
has something it can decode:

  Moment            Sample                                                    Asset prefix
  Ordinary key      InspectorJ — "Computer Keyboard Pressing Single Key
                    Releasing"                                                key-press
  Space bar         Audio Falcon — "Single Keyboard Click Spacebar"          key-space
  Wrong character   Marcello Del Monaco — "wrong answer"                     key-wrong

Files (in public/sounds/, 9 total, ~48 KB):
  key-press.m4a  4,225 B   0.2746 s      key-press.ogg  6,756 B
  key-press.mp3  4,119 B                 key-space.m4a  2,919 B   0.1564 s
  key-space.ogg  5,834 B                 key-space.mp3  2,551 B
  key-wrong.m4a  6,117 B   0.4084 s      key-wrong.ogg  7,466 B
  key-wrong.mp3  5,686 B

Public API:
  KEY_SOUND_SOURCES          the three format lists, keyed by sound name
  primeKeySound()            warm every sample on first user interaction
  playKeySound(now)          an ordinary key
  playSpaceSound(now)        the space bar
  playWrongSound(now)        a wrong character
  playKeystroke(char, correct, now)   route one keystroke to the right sample

ROUTING RULE — exactly ONE sound per keystroke:
  if the character was wrong  -> key-wrong
  else if the character is ' ' -> key-space
  else                         -> key-press
Backspace is silent. Backspace is never "wrong", so it makes no sound.

Design details:
  - Each sound has its OWN pool of 4 preloaded Audio elements, so playback
    never waits on a load and two keystrokes in the same millisecond do not cut
    each other off. Separate pools keep the burst bookkeeping honest: a mistake
    must not be quietened by the letters typed just before it.
  - Repeated presses within a 60 ms burst taper in volume (x0.78, floor 0.16)
    and detune randomly (0.94–1.06 rate, preservesPitch = false) so a long run
    does not sound mechanical.
  - The mistake buzzer is deliberately NOT tapered and NOT detuned: a mistake
    is one event, not a rhythm, and every mistake should read as the same event.
    Volume is a constant 0.5; the ordinary key is 0.45 and space is 0.5.
  - Sample is primed once on the first pointerdown/keydown/touchstart, when the
    browser is willing to decode audio (autoplay policy).
  - ALL failures are swallowed. A browser that blocks autoplay or cannot decode
    the files simply plays the drill silently. Audio must never break typing.

Wired into BOTH runtime scripts:
  src/scripts/lesson-player.ts   the lesson studio
  src/scripts/typing-widget.ts   the timed test widget
Both compute `now` once and pass the SAME timestamp to the engine and to the
sound module, so burst detection follows the engine's clock rather than a
second timer.

LICENSING NOTE (important): these are third-party recordings, NOT covered by
the site's "written for keysprint" claim. InspectorJ's Freesound profile states
the sounds are not public domain and require attribution unless an
attribution-free licence is held. The other two come from Artlist. Confirm the
licences before shipping commercially.

10. THE TIMED TEST WIDGET
================================================================================

Components: src/components/typing/TypingTest.astro, ResultsPanel.astro,
            OptionGroup.astro
Runtime:    src/scripts/typing-widget.ts
Styling:    src/styles/typing.css

  - Same engine, different presentation: a scrolling multi-line passage.
  - Duration options: 15, 30, 60, 180, 300, 600 seconds.
  - Modes: words, sentences, paragraphs.
  - Difficulty: easy, medium, hard.
  - Drill kinds: words, sentences, paragraphs, numbers, punctuation, homeRow.
  - Changing any option swaps the text and resets IN PLACE — no page reload
    mid-test and no layout shift.
  - Ready gate: the passage starts blurred behind a translucent overlay with a
    real Start Test button. The textarea is disabled and nothing is timed until
    Start is pressed; Start lifts the blur and focuses the input, but the clock
    begins on the first accepted keystroke, not on the click.
  - data-typing-area carries data-state="ready|running|completed". The CSS, not
    per-character JavaScript, owns the blur and the overlay, and
    prefers-reduced-motion drops the transition. Restart, a new text, and any
    settings change during a run all cancel the requestAnimationFrame loop and
    return to ready, so a stale callback cannot touch the next test.
  - Full screen: the Full Screen button calls requestFullscreen() on the widget
    root, so the browser hides its own chrome; Escape exits and the button label
    plus aria-pressed follow the fullscreenchange event. Browsers without the
    API (iPhone Safari) get a fixed full-viewport layer with Escape handled in
    script. Full screen is presentation only — it never resets or pauses a test.
  - Performance design: a keystroke touches at most three elements (the
    character just typed, the character deleted, the caret). Completed blocks
    collapse back to plain text once the caret passes them, so live elements
    stay proportional to the text ahead rather than to the test length. All DOM
    writes happen before the single layout read that positions the caret.
  - The URL round-trips: changing a control writes ?duration=&mode=&difficulty=
    and loading that URL restores the same test.
  - Text generation: src/lib/typing/selection.ts, WORDS_PER_LINE = 12 for the
    words drill. Seeded, so a given seed reproduces the same text.

11. PER-KEY ANALYSIS & HEAT MAP
================================================================================

Page:    /typing-analysis/
Runtime: src/scripts/typing-analysis.ts
Styling: src/styles/analysis.css
Model:   src/lib/typing/keys.ts, board.ts

Answers the question a single WPM number cannot: which keys are costing accuracy,
and which finger is responsible?

  - Every finished test records per-key tallies. Each character carries: how many
    times it was pressed, how many of those were correct, and how many times it
    was the expected character but something else was typed.
  - A wrong press is charged TWICE: to the key actually pressed (as wrong) and to
    the key that was expected (as missed). This shows which key your fingers
    actually go to, not just which character you failed to produce.
  - The last 20 results are kept locally (MAX_HISTORY = 20) under
    keysprint.history.v1, together with their tallies.
  - Accuracy bands: >= 95% good, >= 85% fair, below that poor, never pressed
    = unused.
  - The page paints the keyboard heat map, lists past tests, names the weakest
    keys and the least accurate finger, and links each weak key to the right
    drill (home-row keys -> home-row drill, digits -> number drill, remaining
    punctuation -> punctuation drill, other letters -> the lesson index).
  - A clear button removes the stored history and resets the board to "unused".

Keyboard model: a US QWERTY board with the standard touch-typing finger
assignment. Every key has a hand and a finger; every letter of the alphabet
appears exactly once; shifted forms fold into the same physical key. The space
bar is shared and reads "either thumb".

17. DESIGN SYSTEM
================================================================================

  Dark, Vercel-inspired theme with a blue accent.
  Accent:  #60a5fa (dark theme) / #2563eb (light theme)
  Subtle borders, restrained motion, reduced-motion support, visible focus.

  Theme is stored under keysprint.theme and applied by a class on <html>, so it
  is honoured before paint and survives a reload. Headless Chrome reports dark
  mode by default; set keysprint.theme to 'light' or 'dark' to test either.

18. TEXT CORPUS & LICENSING
================================================================================

  - Every passage in src/lib/typing/texts.ts was written for keysprint. Nothing
